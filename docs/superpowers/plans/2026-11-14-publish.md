# Publish 0.1.0 — plan

Spec: `docs/superpowers/specs/2026-11-14-publish-design.md`. Branch `publish-0.1.0`. Every task ends with `pnpm test` green (coverage > 90%) and, where examples are touched, `pnpm e2e:examples`.

1. **Rename** every workspace package: `unstuck` → `@velmlabs/unstuck`, `@unstuck/<x>` → `@velmlabs/unstuck-<x>` (engine, core, protocol, viewer, relay-core, relay-cloudflare; `@unstuck/relay` → `@velmlabs/unstuck-relay`). Update imports, the SDK engine lookup (`@velmlabs/unstuck-engine-<platform>-<arch>`), tests, e2e, examples (drop the aliases), scripts. Test first: an engine-lookup test expecting the new package name; a repo-wide check that no `@unstuck/` or `from 'unstuck'` remains outside docs/history.
2. **Compile** protocol, core and sdk-ts to `dist/` (ESM + `.d.ts`); `exports`/`main`/`types` → `dist`; `files`; per-package README + LICENSE; `repository`/`homepage`/`author`. Test: `pnpm pack` of each contains only `dist/`, `package.json`, `README.md`, `LICENSE`, and the packed SDK imports and runs from a clean folder.
3. **Engine for 5 platforms + launcher**: `scripts/release/build-engines.mjs` cross-compiles with `bun build --compile --target=bun-<os>-<arch>`; generates the platform packages (`os`/`cpu`, `bin/`); the launcher `engine/bin/unstuck-engine.js` (resolve, spawn, forward stdio/exit/signals; clear error for unsupported platforms). Tests: launcher unit tests (resolution, unsupported platform, exit code forwarding); each binary's file type.
4. **Python wheels**: `scripts/release/build-wheels.mjs` builds the wheel per platform with the binary in `src/unstuck/_bin/` and retags it. Test: wheel contents and tags; a fresh venv install of the linux x64 wheel finds its bundled engine.
5. **`scripts/release.mjs`** (`--dry-run` default, `--publish`): build all → `release/`; content checks; clean-folder TS Quickstart takeover; fresh-venv Python takeover; MCP `tools/list` through the launcher; binary types; registry check that 0.1.0 isn't taken. `--publish` runs the dry run first, then publishes in order (protocol, core, 5 engines, engine, sdk; wheels) with `NPM_TOKEN` and the PyPI credential. Tokens never printed or written into the repo.
6. **Dry run**, then **publish** (needs `NPM_TOKEN` in the session and the PyPI credential), then verify from the public registries in a clean folder.
7. **Cloud repo follow-up**: re-vendor with the new names and update its imports; switch landing/dashboard install text; `DOCS_READY=1` for production; apply the README draft to the open-source repo.

Final review by a fresh reviewer before step 6's publish.
