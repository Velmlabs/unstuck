# Intel Macs in 0.1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the darwin-x64 engine (npm platform package and `macosx_13_0_x86_64` wheel) in 0.1.1, ad-hoc re-signed with rcodesign so its code signature is valid.

**Architecture:** The release build downloads a pinned rcodesign, checks its SHA-256 and caches it under `release/tools/`. After Bun compiles darwin-x64, `rcodesign sign` replaces Bun's stale signature. A stricter `macosInfo` checks the result: page hashes, a code limit that reaches the signature, and special-slot hashes. The platform joins `PLATFORMS`, and every package moves to 0.1.1.

**Tech Stack:** Node ESM scripts (`scripts/release/*.mjs`), vitest, Bun cross-compile, rcodesign 0.29.0 (apple-codesign), uv/wheel.

**Spec:** `docs/superpowers/specs/2026-11-14-intel-mac-design.md`

## Global Constraints

- rcodesign: `https://github.com/indygreg/apple-platform-rs/releases/download/apple-codesign%2F0.29.0/apple-codesign-0.29.0-x86_64-unknown-linux-musl.tar.gz`, SHA-256 `dbe85cedd8ee4217b64e9a0e4c2aef92ab8bcaaa41f20bde99781ff02e600002`, binary at `apple-codesign-0.29.0-x86_64-unknown-linux-musl/rcodesign` inside the archive.
- darwin-x64 platform: `{ id: 'darwin-x64', bun: 'bun-darwin-x64-baseline', os: 'darwin', cpu: 'x64', wheel: 'macosx_13_0_x86_64', exe: 'unstuck-engine', minMacos: '13.0', resign: true }`, placed right after darwin-arm64.
- Ad-hoc signing only: `rcodesign sign --binary-identifier unstuck-engine <file>`. Keep the flags and entitlements rcodesign carries over from Bun's own signature (hardened runtime plus Bun's five `com.apple.security.cs.*` entitlements); that is how Bun ships its official x64 binary. No certificate, no notarisation.
- darwin-arm64 is not re-signed.
- Version `0.1.1` everywhere 0.1.0 appears today (package.json files, `engine/src/version.ts`, `sdk-ts/src/version.ts`, `sdk-py/pyproject.toml`, `sdk-py/src/unstuck/_version.py`, `VERSION` in `scripts/release.mjs` and `scripts/publish.mjs`, and tests that pin it).
- `rcodesign verify` is not used: it says it "is known to be buggy" and fails on correct ad-hoc signatures.
- Commit as `Velm Labs <velmlabs@users.noreply.github.com>`, no AI attribution; coverage > 90% in `scripts/` (`pnpm test:scripts`).

## Review Focus

1. A tampered or truncated rcodesign download: the build must stop before signing, not run an unknown binary. (Task 1 test: wrong checksum throws, nothing is left in the cache.)
2. A signature that doesn't reach the end of the code, which is 0.1.0's exact failure: it must read `invalid` even when every page it does cover matches. (Task 2 test.)
3. An entitlements or requirements blob changed after signing: `invalid`. (Task 2 test.)
4. An Intel Mac user on an old launcher or a stale cache: npm resolves `@velmlabs/unstuck-engine-darwin-x64@0.1.1` through the launcher's exact-version optional dependency. (Task 3 test: the launcher manifest lists all five at the same version.)
5. A wheel claiming an older macOS than the binary: the dry run's `minos === minMacos` check also covers darwin-x64. (Task 3: `release.mjs` runs the macOS checks for every darwin platform.)

### Task 2: Stricter signature check

**Files:**
- Modify: `scripts/release/build-engines.mjs` (`macosInfo`)
- Test: `scripts/release/build-engines.test.mjs`

**Interfaces:**
- Consumes: `ensureRcodesign`, `adhocSign` (Task 1).
- Produces: `macosInfo(file) -> { minos: string, signature: 'valid' | 'invalid' | 'missing', flags?: number }`. It is `valid` only when every code page matches, the CodeDirectory's codeLimit equals the LC_CODE_SIGNATURE offset, and each special slot whose blob is present (requirements 2, entitlements 5, DER entitlements 7) hashes to its stored value.

- [ ] **Step 1: Write the failing tests** (in the existing `macOS builds` block, which already builds darwin-arm64):
  - Bun's raw darwin-x64 build → `signature: 'invalid'`.
  - The same file after `adhocSign` → `{ minos: '13.0', signature: 'valid' }`, with the ADHOC flag (`0x2`) set.
  - A copy whose signature covers every page but whose codeLimit has been lowered by one page, with the page count and hashes truncated to match → `invalid`. Write a small helper in the test to do the editing.
  - A signed copy with one byte flipped inside the entitlements blob → `invalid`.
  - Darwin-arm64, unchanged → still `valid`.
- [ ] **Step 2:** Run; the codeLimit and entitlements cases fail on the current check.
- [ ] **Step 3:** Extend `macosInfo`. Special slot `-n` is stored at `hashOffset - n*hashSize` and hashes the blob of type `n` in the SuperBlob; skip slots with an all-zero hash or no blob.
- [ ] **Step 4:** `pnpm test:scripts` passes.
- [ ] **Step 5:** Commit `build: the signature check also needs full code coverage and matching special slots`.
